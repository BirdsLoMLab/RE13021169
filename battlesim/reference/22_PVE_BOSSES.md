## Reading the Numbers

Combat stats use **fixed-point integers** divided by 10,000 (LOM convention):

| Stat | Raw value | Effective |
|------|-----------|-----------|
| `crit_def` | `10000` | 1.00× crit-damage divisor (no reduction) |
| `crit_def` | `100000` | 10.00× — caps player crits at the floor of 1.5× |
| `miss` / `hit` | `8000` | 80% (evasion / accuracy) |
| `att_resist` / `skill_resist` / `partner_resist` | `2000` | 20% incoming-damage reduction |
| `att_dam` / `skill_dam_extra` | `100000` | 10.00× ATK multiplier |
| `att_speed` | `14000` | 1.4 attacks per cycle |

**Crit damage formula:** `final_crit_mult = max(1.5, crit_dam / max(0.5, crit_def))`
With player `crit_dam = 5.0×` and boss `crit_def = 10.0×`, crit multiplier = `max(1.5, 0.5)` = **1.5×** (the floor).

## Critical Finding: boss_def & pve_resist Are Player-Side

Every PvE boss in the dump ships with `boss_def = 0` and `pve_resist = 0`. These are **player** stats — they reduce damage *you take from* boss/PvE attacks. Bosses don't directly resist `boss_dam` or `pve_dam`; their only crit defense is `crit_def`, and their only dodge is `miss`.

## How to Decode More Bosses

If you find a boss table not covered above, the recipe is:

1. Locate the table's schema in `data/schemas/Config<Name>.json`. Note which fields are `bignum` (HP, ATT, DEF on player units) vs `xor_number` (everything else).
2. Find the actual data in `/tmp/lom_tables/<Name>.json` (run `decode_config_data.py` against the bundle in `uploads/`).
3. Decode `bignum` fields with **XOR key 534862510** (multi-chunk: `value = nums[0]^k + (nums[1]^k)*1e9 + …`). Decode `xor_number` fields with **CONFIG_KEY 24455**.
4. Resolve `bossID` / `unitId` references against the merged `Unit.json` + `MainUnit*.json` index.

The build script for this database is `/tmp/build_boss_db.py` (kept locally for reproducibility — not checked in).
